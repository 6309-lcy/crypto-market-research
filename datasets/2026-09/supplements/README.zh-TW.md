# 九月研究：補充資料與完整性界線

原先固定的九月費率、每小時 K 線與資料集雜湊均保持不變。

## 已下載

四間交易所共 **60 個市場的現行合約規格**，包括可取得的價格精度、下單數量精度、最小數量與 OKX 合約面值。原始公開 API 回應與擷取時間均保留，整理後資料是 [instrument_metadata.json](instrument_metadata.json)，雜湊見 [manifest.json](manifest.json)。

**這些是目前規格快照，尚未確認九月是否相同。** 它們不能直接證明歷史下單限制或實際帳戶費用。公開 API 未提供的最小名目本金或 tick 規則維持空值。

## 各研究仍需要甚麼

| 研究目標 | 已有 | 尚缺 |
| --- | --- | --- |
| 費率持續性、低換手訊號 | 四間共同月份的實際結算與每小時價格 | 預先定義訓練／測試規則及成本假設 |
| 精確資金費損益 | 真實結算費率、部分結算標記價格 | Hyperliquid 歷史 oracle，其他交易所精確結算估值 |
| 可成交基差套利 | 每小時成交價代理 | 同步買賣盤、足夠深度、接收時間、歷史下單限制 |
| Maker 成交與低費用優勢 | 現行規格 | L2 更新、逐筆成交、序號、排隊及延遲模型、帳戶費率 |
| 原本結算前預估費率訊號 | 最終結算費率 | 當時逐時的預估費率觀察紀錄 |

逐筆成交和 L2 快照各自都不足以證明自己的掛單會成交。精確帳戶淨收益也需要當時費率等級、保證金與資金調度條件。

## 已查證的存取限制

[匿名查詢證據](source_access.json) 保留公開來源、查詢日期和狀態碼。Binance／Bybit 的單一九月 BTC 成交封存 HEAD 查詢成功；這只證明該檔可存取，完整月份與其他幣種尚未大量下載或逐檔驗證。

Hyperliquid 九月 1 日、30 日的 asset contexts 候選檔，以及九月 1 日 BTC L2，匿名請求均回傳 403。這代表存取被拒，不能推論檔案不存在。官方封存採 AWS requester-pays，需可用 AWS 存取與下載費用授權；官方亦提醒更新可能延遲、資料可能缺漏。尚未執行任何付費下載。

官方說明：https://hyperliquid.gitbook.io/hyperliquid-docs/historical-data

## 買賣盤來源的補充發現

Bybit 的 200 檔買賣盤、OKX 的價位級 L2 封存樣本可公開存取；已核對樣本格式，尚未下載整月或驗證更新連續性。BTC 單日壓縮買賣盤約為 Bybit 181 MB、OKX 379 MB，跨幣種整月資料會很大。OKX 成交封存以 UTC+8 分區、買賣盤以 UTC 分區，必須按實際事件時間對齊。

Binance 公開 `bookDepth` 是按價格百分比距離匯總的深度，不能代替價位級 L2；已查詢的九月 BTC `bookTicker` 前綴為空。因此即使補齊 Hyperliquid，四間完整 maker 回測仍有 Binance 歷史價位級簿記的來源缺口。

可行的公開資料路線是先做 **Bybit／OKX、單一幣種、相同數日**的買賣盤加成交重播，驗證序號及連續性，再擴大範圍。完整來源細節見 [英文說明](README.md)。

## 結論與下一步

目前可以繼續做有明列價格及成本假設的費率研究；資料尚未完整到足以聲稱精確 oracle 損益或 maker 實盤成交。

取得 Hyperliquid AWS 存取後，應先檢查九月檔案目錄、大小、欄位和抽樣覆蓋，估算成本，再補齊 oracle／mark 及相關簿記；其後才下載各交易所同時段買賣盤與成交並同步驗證。這份補充先把可以取得與仍被阻擋的部分分清楚。
